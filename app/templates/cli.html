Standalone CLI Client & Embedded SDK v2.1

MaazDB Standalone CLI (maazdb-cli) is a highly responsive, zero-dependency command-line terminal client. This document outlines the standalone client architecture, embedded async engine, command-line formatting and execution parameters, and local REPL slashed overrides.

1. Standalone Crate Architecture (sdk-cli)

To maximize compilation efficiency, reduce binary overhead, and eliminate circular workspace dependencies, maazdb-cli is completely decoupled from the external maazdb-rs driver crate.

Built-In Client Engine (src/sdk.rs)

The CLI embeds its own implementation of the asynchronous, multiplexed MaazDB Protocol v2.1 client directly in src/sdk.rs. This provides several advantages: * Zero Dependency Lock-In: The CLI can be updated, compiled, and deployed independently of other driver targets. * Unified Build Footprint: Eliminates the need to link external client libraries, generating a single standalone binary. * Custom Protocol Optimization: Tailored specifically to the CLI's requirements, such as custom driver signatures (maazdb-standalone-client-v1) to allow the server to easily audit administrator sessions.

2. Command-Line Interface (CLI Options)

The CLI binary supports direct terminal interactions using standard GNU-style double-dash flags, single-character options, and positional fallbacks.

Option Reference Table

Flag Alternative Description
-h --help Prints the help menu and lists examples.
-c --config Launches the interactive setup wizard with secure password masking.
-m --monitor Opens the terminal-based (TUI) real-time system monitor.
-s --source Executes a local .sql script sequentially and exits immediately.
-f --format Dynamic output formatter. Supports table, json, csv, or tsv.
None [path/to/file.sql] Bypasses flags; executes the file directly if detected on disk.

Usage Examples

Run Script in JSON Format:

maazdb-cli -f json /var/lib/maazdb/backups/seed.sql

Run Script in CSV Format (Positional Detection):

maazdb-cli -f csv /mnt/shared/maazdb-proj/maazdb/tests/suite.sql

Launch REPL with TSV Output:

maazdb-cli -f tsv

Note for Cargo users: Remember to use the -- double-dash token to prevent Cargo from consuming your flags:

cargo run --bin maazdb-cli -- -f json script.sql

3. Interactive REPL Features & Slashed Shorthands

The entire terminal runtime runs within a non-blocking #[tokio::main] wrapper, allowing query execution to operate over an active multiplexed socket.

Standard Shell Intercepts

When running in interactive REPL mode (maazdb>), certain commands are caught locally by the client parser before being sent over the network, saving server round-trips: * help : Displays the interactive shell commands and keyboard shortcuts. * clear : Instantly clears the screen buffer. * exit / quit : Shuts down active background writer/reader tasks and terminates the process.

Script Loading: S and SOURCE

To run local scripts from inside the shell, the parser supports both the verbose standard command and an abbreviated shorthand: * Shorthand: S '/path/to/file.sql'; * Verbose: SOURCE '/path/to/file.sql';

Slashed Database Shorthands (Postgres-Style)

For faster database management, you can use local slash-intercept commands inside the terminal shell: * \l : List all tables in the current database (SHOW TABLES; shortcut). * \d <table_name> : Describe table structure (DESCRIBE <table_name>; shortcut). * \c <db_name> : Switch active database schema (USE <db_name>; shortcut). * \format <type> : Switch output formatting dynamically on-the-fly (table, json, csv, tsv).

4. Internal Implementation & Resiliency Blueprint

The CLI's design relies on clean task-separation over a single TCP socket:

                  +-----------------------------------+
                  |      maazdb-cli Thread Loop       |
                  +-----------------------------------+
                     /                             \
        (Query Spawn)                               (Packet Read)
                   v                                 v
   +-------------------------------+      +-------------------------------+
   |      Async Writer Task        |      |      Async Reader Task        |
   +-------------------------------+      +-------------------------------+
   | Pulls packets from mpsc queue |      | Parses 8-byte framing headers |
   | Writes payload to TcpStream   |      | Routes via Request ID         |
   +-------------------------------+      +-------------------------------+
                   \                                 /
                    v                               v
                  +-----------------------------------+
                  |      Secure TLS 1.3 TcpStream     |
                  +-----------------------------------+

Self-Healing Auto-Reconnection (Keep-Alive Resilience)

Network interruptions (such as VPN drops on high-latency channels) can break active sockets. To prevent execution errors: 1. The client intercepts the ConnectionClosed signal. 2. It pauses the current command and attempts to establish a fresh TCP/TLS connection using the loaded persistent config. 3. Upon successful cryptographic handshake, the client transparently re-issues the query in the background.

5. 0-RTT Safe Flight Auto-Tagging

Protocol v2.1 introduces support for TLS 1.3 0-RTT connection times. To prevent mutating queries from being replayed on public networks, the client implements an automatic evaluation layer:

  • Statement Inspection: When a query is passed to the SDK, the SQL is normalized and evaluated locally.
  • Flag Injection: If the query is read-only (SELECT, SHOW, DESCRIBE, or DESC), the client automatically attaches the FLAG_EARLY_DATA (0x02) bitmask to the packet header.
  • Mutating Protection: Mutating queries (INSERT, UPDATE, DELETE, etc.) bypass 0-RTT early data flags to guarantee transactional integrity on the server side. ```
